# Модуль «Задачи»

## Что добавлено

- В основную навигацию добавлен приватный раздел «Задачи».
- Стартовое представление — «Сегодня»: просроченные задачи, активные задачи на сегодня, выполненные и ближайшие.
- Быстрое создание задачи с названием и датой; в подробной форме доступны описание, время, приоритет и статус.
- Минимальные статусы: «К выполнению», «В работе», «Выполнено».
- Быстрые действия: выполнить, вернуть в работу, перенести на завтра, редактировать и удалить.
- Представления «Сегодня», «Все задачи» и Kanban.
- В Kanban личные задачи можно перетаскивать между статусами. Обновление интерфейса оптимистичное; при серверной ошибке состояние откатывается.
- На мобильном экране используется вертикальный список, а форма добавления остаётся доступной сверху.

## Откуда берутся задачи

1. Личные задачи создаются пользователем с ролью `owner` — это текущий редактор/владелец рабочей панели.
2. Запланированные материалы существующего календаря отображаются в задачнике как read-only-проекция. Они не копируются в таблицу задач и не создают второй источник истины.

Календарная карточка открывает существующий календарь на нужном месяце. Редактирование и перенос таких записей по-прежнему выполняются календарём.

## Как определяется «Сегодня»

Дата сравнивается с локальной датой браузера в формате `yyyy-MM-dd`. Задача с датой меньше сегодняшней и статусом, отличным от `completed`, попадает в компактный блок «Просрочено». Выполненные задачи не удаляются и остаются в истории текущего дня.

## Перенос

«На завтра» прибавляет один календарный день к `dueDate`. Выбор произвольной даты доступен в редакторе задачи. После сохранения задача сразу перемещается в соответствующее представление.

## Permissions и хранение

- Ручной раздел скрыт для `guest` и `designer`; проверка доступа выполняется также на уровне источника данных при использовании Supabase.
- Для Supabase добавлена миграция `database/003_personal_tasks.sql`.
- Таблица `personal_tasks` привязана к `auth.users.id` через `owner_id` и защищена RLS-политиками select/insert/update/delete. Политики используют текущую сессию и существующую функцию `is_workspace_owner()`; `owner_id` не принимается из формы.
- `workspace_state` не содержит личные задачи и продолжает использоваться для общей гостевой рабочей области.
- Без Supabase задачи хранятся локально в `localStorage` текущего браузера.
- Если в dev-режиме Supabase уже подключён, но миграция ещё не применена, включается явный локальный fallback с уведомлением. В production при недоступной таблице изменение откатывается.

## Изменённые файлы

- `src/components/content-plan-fact-app.tsx` — страница, проекция календаря, CRUD задач, Kanban, локальная/облачная синхронизация и навигация.
- `src/lib/types.ts` — типы `PersonalTask`, `TaskStatus`, `TaskPriority`.
- `src/lib/supabase.ts` — загрузка и сохранение личных задач через текущую Supabase-сессию.
- `database/003_personal_tasks.sql` — таблица и RLS-политики.

## Внешние референсы

Функциональные паттерны сверены с указанными в ТЗ OpenKanban, simple-project-management, ProjectHub и Kanban-компонентами 21st.dev. Код этих проектов не копировался, зависимости не добавлялись; новый UI использует существующие `Button`, `Modal`, `Field`, `AppSelect`, motion и дизайн-токены SaaS.

- `npm run lint` — пройдено.
- `npm run build` — пройдено, статический маршрут `/` собран Next.js 16.3.5.

## Важная эксплуатационная заметка

Перед production-использованием Supabase нужно один раз выполнить `database/003_personal_tasks.sql` после существующих миграций `001` и `002`. Это необходимо для настоящей приватности задач на сервере; локальный fallback предназначен только для разработки и предпросмотра.
